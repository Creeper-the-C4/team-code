## 1. 单位与滤波之谜：我的判断，以及最小诊断脚本

### 1.1 物理判断：现有证据更支持“单位是 g 的自由加速度”，与论文声明的 m/s² 相反

我对 30 人的 `channel_quality.csv` 做了汇总，并结合 `physics_diagnostics.csv`。以下四条证据可以相互印证：

| 证据 | 如果单位是 m/s² | 如果单位是 g |
| :--- | :--- | :--- |
| 静立时自由加速度模长中位数为 0.0125。去重力后的残差约等于 $g\sin\delta$，$\delta$ 是倾角估计误差 | 对应 $\delta\approx0.07°$。消费级 IMU 的姿态精度达不到这个水平，**不合理** | 对应 $\delta\approx0.7°$，是典型的 AHRS 精度，**合理** |
| 超过 100 万帧跳跃中，Head 的 Acc_Y 全局最小值为 −4.07，LowerBack 中位最小值为 −2.73 | 腾空自由落体应出现约 −9.81 的平台，但头部从未达到，**矛盾**（除非数据被极强滤波） | 腾空平台应约为 −1；低于 −1 的尖峰是起跳或落地时皮肤与软组织的振铃，**合理** |
| 全部数据的 Acc_Y 标准差：LowerBack 约 0.53，Head 约 0.49 | 跑步和跳跃约占 1/6 的数据，它们的骨盆竖直加速度标准差真实值应为 8–10 m/s²，整体标准差应在 3–4 以上，**偏小约 8 倍** | 跑步和跳跃的标准差约 1 g，整体约 0.5，**量级吻合** |
| 极值：RightShank 最小 −71.9，RightFoot 最大 +47.8 | 换算成 g 是 7.3 g 和 4.9 g，冲击量级合理 | 72 g 不合理，但这只是少数瞬态尖峰或毛刺，不代表整体量级 |

**结论**：除了胫骨和足部的个别极值外，其余证据都指向 g。所谓“Head −4 vs Foot +48”的矛盾，在 g 单位下可以解释为：躯干是正常量级，足部和胫骨有冲击瞬态或尖峰。不过这仍然只是推断，需要 1.2 节的判决性实验来确认。

### 1.2 同一现象的另一面：数据可能经过了厂商处理

- 足部静立时的模长只有 **0.0012**，比其他节段（0.009–0.035）**小一个数量级**，可能低于 MEMS 加速度计的本底噪声。这暗示足部加速度被厂商的接触约束（类似 ZUPT）压制过。
- 陀螺与四元数导数拟合的增益只有 0.84–0.96，躯干最低，说明四元数有滤波滞后。
- 足部陀螺最大值约 51.6 rad/s（约 2960°/s）。这个数值需要与设备的陀螺量程对照。如果超出量程，说明它是推导量而不是原始测量。

**影响**：如果确实是厂商处理过的数据，Task 3 中“测量一致性”和 ZUPT 的结果有一部分反映的是厂商自身的约束，存在循环论证风险。论文表述需要更保守，V2 参照应以陀螺为主，因为陀螺最可能是原始测量。

### 1.3 云端最小诊断脚本 T1–T6（都只需 CPU，单人跑几分钟；VM 可以按 loader API 写好后交付）

| 编号 | 检验 | 方法 | 判据（区分度） |
| :--- | :--- | :--- | :--- |
| **T1** | 跳跃腾空平台 | 在活动 11 的试次中，找全部 17 个传感器的 Acc_Y **同时**低于阈值的帧，即全身处于弹道相，统计这些帧的众数 | 众数约 −1 表示 g，约 −9.81 表示 m/s²；同时要求腾空时各传感器读数近似一致（全身共同自由落体） |
| **T2** | 楼梯升高积分 | 对上楼梯试次，将 LowerBack 的 Acc_Y 乘以 $s$ 后做两次积分，以步态周期为单位分段去趋势，求每步净升高 | 每步应为 0.15–0.18 m。取 $s=9.81$ 时合理则单位是 g，取 $s=1$ 时合理则是 m/s²；**两者相差 10 倍**，对滤波不敏感 |
| **T3** | 膝关节杠杆臂回归（即“向心加速度回归”） | 刚体约束：$s(a_{th}-a_{sh}) = [\dot\omega]_\times$ 与 $[\omega]^2_\times$ 项乘以 $R_{th}r_1-R_{sh}r_2$。$\omega$ 是已确认的世界系 rad/s 陀螺，$r_1, r_2$ 是体系下的常向量，共 6 个未知数，用线性最小二乘求解 | 拟合出的 $\|r_1\|$ 应接近大腿传感器到膝的距离（约 0.3–0.4 m）。按 g 解释时，原单位下的拟合值会小 9.81 倍。另外，**R² 接近 1 说明加速度来自刚体骨架推导**，原始 IMU 因软组织影响 R² 会明显低于 1 |
| **T4** | 静立残差与倾角 | 已有数据，0.0125 对应 0.7° 还是 0.07° | 作为辅助证据（见 1.1 表） |
| **T5** | 膝铰链诊断（001 回执 A3），不受安装偏差影响 | 计算 $\omega_{rel}=R_{th}^\top(\omega_{sh}-\omega_{th})$，对它做 PCA。两种来源各算一次：**陀螺来源**，以及**四元数差分来源** | 理想铰链下，$\omega_{rel}$ 在大腿系里始终平行于固定轴，即 $\sigma_2/\sigma_1\approx0$，而且这与传感器怎么安装无关。如果**四元数来源接近一维而陀螺来源不是**，说明四元数经过骨架约束解算、陀螺是原始数据。这一结果直接决定 V1 和 V2 参照的独立性怎么写 |
| **T6** | 量程与噪声底 | 统计 $\|\omega\|$ 超过 34.9 rad/s（2000°/s）的帧数，以及静立段各传感器 Acc/Gyr 的标准差 | 与设备规格对照（规格需要查原论文或 Noitom 文档），判断足部的数据是否被处理过 |

**建议先跑 T1 和 T2**：它们最快，判别力最强（10 倍差距）。单位确定之后，Froude 数、接触锚点、Task 3 的重力项都要相应改写。

## 2. Task 1 升级：物理建议（针对 2361e33 暴露的问题）

> **先说评估纪律**：2361e33 的外层测试结果大家都已经看过。后续升级应当**根据物理动机预先确定一组方案（相当于预注册），在验证集参与者上确认后，只在外层测试上运行一次**，并如实写明“测试集已被查看一次”。不要根据外层分数反复挑选方法。

### 2.1 三档步行崩盘（P07 三档步行 F1=0.33，P17、P25 也很差；中速 F1=0.836）

1. **2 秒窗的分辨率不够，这是硬伤。** 2 秒窗的频率分辨率是 0.5 Hz，而三档速度之间的步频差只有约 0.1–0.2 Hz，按物理原理就分不开。
   - 改用 4–8 秒窗，并用**自相关求周期，加抛物线亚样本插值**，分辨率可以远小于 0.05 Hz。
   - 信号源选大腿的矢状面角速度，它周期性最干净。
2. **按传感器各自做航向不变化，比我 002 信里的建议更简单。** 用传感器**自身**的四元数把世界系向量转到体系：$v_b=R(q)^\top v_w$。这样得到的 Acc/Gyr 对航向严格不变，而且只依赖这一个传感器，不会破坏按单元屏蔽。
   - 体系下的大腿 Gyr 就是矢状面角速度，方向与人朝向无关。
   - 竖直分量 $Y_w$ 本身就不随航向变化，保留即可。
3. **从运动学估计速度，不靠积分漂移，这也解决了红线 #7 的问题。**
   - 步长 $\ell\approx 2L\sin(\Delta\theta_{hip}/2)$，其中 $L$ 是人体测量表中的腿长，$\Delta\theta_{hip}$ 是大腿角摆幅；
   - 速度 $\hat v=\ell\,f_{step}$；
   - Froude 数 $\widehat{Fr}=\hat v^2/(gL)$，无量纲步频 $f\sqrt{L/g}$。
   - 论文中标注为“运动学估计速度”，不称为实测速度。
4. **按有序类别建模。** 慢、中、快是有顺序的，中速夹在中间，两侧的误差都会落到它身上。可以用有序分解，例如 $P(>\text{慢})$ 和 $P(>\text{中})$ 两个二分类，或者对 $\hat v$ 回归后再设阈值。这样可以减少慢和快之间的远距离混淆。
5. **可声明的个人标定协议，单独报告。** P07 的结果像是“整体平移”：每个人的三档速度是相对于自己而言的。
   - 题目 Task 2 本身就要求说明“精简系统还需要哪些标定信息”。可以设计一个协议：每位用户先提供**一段无标签的常速步行**，把特征换算成相对于它的值。
   - 结果标注为“带标定”，与“无标定”结果并列报告。
   - 严禁使用测试者的标签；无标签的被试内标准化属于转导式方法，必须明确声明。
6. **先查标签协议**（见第 4 节 Q2）：速度是自选的还是规定的？如果是跑步机定速，第 3 和第 5 条要换成绝对量的写法。

### 2.2 划船被误判为坐（873 窗，占 5.17%）

1. **窗长**：一桨约 2–3 秒，2 秒窗可能只截到桨叶入水或回桨时近似静坐的那一段。改为 ≥4 秒窗，或者多尺度窗。
2. **周期性特征**：在体系下的大腿和小腿 Gyr 上，计算 1.5–3.5 秒滞后处的自相关峰；再加上**膝关节相对旋转幅度**（大腿与小腿的相对姿态）。划船时膝关节屈伸约 100° 以上，静坐时几乎不动。
3. **粘性 HMM**：可以消除划船片段中零星被误判成“坐”的孤立窗口。
4. **先做一个定位统计**：这 873 窗位于试次的哪个位置？如果集中在划船试次的开头和结尾，那其实是“标签边界语义”问题（准备动作也被标成了划船），而不是模型能力问题，论文的写法也就不同。

### 2.3 Others 被误判为站/躺/坐（1197 + 920 + 556 窗）

这完全符合预判：Others 和静态姿态之间的区别主要在于上下文，瞬时信号区分不了。处理方式维持 V3：
- 13 类监督学习；
- 带时长先验的粘性 HMM 或 HSMM；
- 逐帧评估。

### 2.4 P25–P30 的结构异常：这本身是一个重要发现

- P26–P30 每人有 159–260 个试次，混合窗只占 0.13%–0.56%；P01–P24 的混合窗占 2.3%–6.9%。这强烈提示**后 5 到 6 人是另一批采集，或者试次切分方式不同**（可能是一个试次只含一个活动）。
- 影响：过渡窗和 Others 的构成、HMM 的有效性、跨批次泛化都会受影响。**建议所有结果按批次（P01–P24 和 P25–P30）分层报告。**
- 另外，最差的 P07、P25、P01、P13 全部落在 fold 0 的测试集里。fold 0 的 F1 为 0.867，是 6 折中最差的。
- 第 4 节 Q2 请 GPT 查原论文中关于批次的说明。

  3. VM 以 bundle 或 patch 交付，由有云端权限的一方运行；结果只回传小文件（CSV、JSON、PNG），通过仓库或协作区传递。
